6. MAIN USER FLOW
==================================================

The core flow should be:

1. User opens platform.
2. User signs up/logs in.
3. User completes profile.
4. User chooses:
   - Find a Ride
   - Offer a Ride
5. User enters:
   - Starting location
   - Destination
   - Date
   - Time
   - Number of seats
6. Platform searches compatible rides.
7. Platform calculates route similarity/matching score.
8. User sees matching rides.
9. User opens ride details.
10. User requests to join.
11. Driver accepts/rejects.
12. Passenger receives status.
13. Confirmed passengers appear in ride.
14. Users can view upcoming rides.
15. Ride can be completed/cancelled.
16. Users can provide ratings/reviews after completed rides.

10. SMART MATCHING ENGINE
==================================================

This is the most important feature.

Create a matching service.

Inputs:

Passenger:
- origin
- destination
- date
- preferred time
- flexibility

Driver ride:
- origin
- destination
- date
- departure time
- available seats

Calculate:

- route similarity
- origin proximity
- destination proximity
- time compatibility
- available seats
- detour tolerance

Create a score between 0 and 100.

Example conceptual scoring:

Route similarity: 40%
Origin proximity: 20%
Destination proximity: 20%
Time compatibility: 15%
Seat availability: 5%

Make these weights configurable.

Do not pretend the algorithm is real-world navigation accuracy if no map routing provider is configured.

Create a clean matching service abstraction so a real routing API can be integrated later.
